# ext_eval: external evidence harness

Three pieces that push the tool towards real-world conditions and say plainly where it stops. Nothing here edits `backend/app`; all data is fictitious (our generator) or a public dataset read as plain data files. No downloaded code is run.

| Piece | File | Purpose |
|---|---|---|
| Real-OCR mode | `real_ocr.py`, `real_ocr_eval.py` | send scan, photo and simulated renders through the repo's own OCR (Apple Vision via `ocrmac`) instead of the oracle, and compare extraction and rule outcomes side by side |
| Print-scan / camera simulator | `scan_sim.py` | deterministic, seeded degradation of rendered pages in three severities (SIMULATED) |
| External forensic runner | `forensic_runner.py`, `realtext_breakdown.py` | the repo's image-forensics checks on external forged/genuine images, with Wilson intervals and mask localisation; the second script cuts the RealText-V2 rows by edit size |
| DocSplit topologies | `docsplit_eval.py` | the statement-assembly code under DocSplit's real upload arrangements (labels only; page content synthetic) |
| FraudRAG-style local test | `fraudrag_local.py` | five published fraud categories re-implemented as simple PDF statements, naive and consistent variants, run through the real pipeline |

All commands run from the repo root with `uv run`. Long jobs: run them with `nohup ... &` and poll the log.

## 1. Simulated print-scan and camera renders (`scan_sim.py`)

A physical print-and-scan was not possible, so the renders are labelled SIMULATED everywhere: the folder name (`scan_sim_*`), the manifest (`"simulated"`), the PDF producer, the JPEG comment.

Pipeline per page: render at 200 dpi, ink coverage, bleed and dot gain, halftone screen at 45 degrees, ink on tinted paper, paper grain and mottling, rotation and perspective warp (with a desk or scanner-lid border), uneven light, vignette and shadows (an edge shadow plus a blob), disk defocus and linear motion blur, downscale to the output dpi, Gaussian plus shot noise, then a JPEG recompression chain. Every parameter is drawn uniformly from the range of the chosen level, seeded by `(seed, level, file, page)`: two runs give byte-identical files.

| Parameter | light | med | heavy |
|---|---|---|---|
| story | decent flatbed scan | office MFP scan or careful phone photo | hurried phone photo, low resolution, forwarded through a messaging app |
| output resolution (dpi) | 200 | 150 | 100 |
| rotation magnitude (deg, random sign) | 0 to 0.5 | 0.4 to 1.5 | 1.5 to 3.5 |
| perspective corner jitter (fraction of page) | 0 | 0.004 to 0.012 | 0.015 to 0.035 |
| background border (fraction of canvas) | 0 | 0 to 0.02 | 0.03 to 0.07 |
| dot gain (extra mid-tone ink coverage) | 0.02 to 0.06 | 0.06 to 0.12 | 0.12 to 0.2 |
| halftone blend (0 none, 1 full screen) | 0 | 0.25 to 0.45 | 0.5 to 0.8 |
| halftone period (px at 200 dpi) | 5 | 5 to 7 | 4 to 6 |
| paper grain and mottling amplitude | 0.008 to 0.02 | 0.02 to 0.04 | 0.04 to 0.07 |
| uneven lighting (relative) | 0.02 to 0.06 | 0.06 to 0.15 | 0.15 to 0.3 |
| vignette strength | 0 | 0.05 to 0.12 | 0.15 to 0.3 |
| shadow darkening | 0 | 0 to 0.12 | 0.15 to 0.35 |
| defocus disk radius (px at 200 dpi) | 0.3 to 0.7 | 0.7 to 1.2 | 1.2 to 2 |
| motion blur length (px at 200 dpi) | 0 | 0 to 3 | 2 to 7 |
| Gaussian sensor noise (0-255) | 1.5 to 3 | 3 to 5 | 5 to 8 |
| signal-dependent noise factor | 0.2 to 0.5 | 0.5 to 1 | 1 to 2 |
| JPEG chain | q88 | q85 then q70 | q80 then resize x0.8, q60 then q50 |

Motion blur is applied when the drawn length is at least 1.5 px. Rotation magnitude has a random sign. The table above is generated by `scan_sim.py levels` and a test keeps it in sync with this file.

```
# build light, medium and heavy renders (one image-only PDF per document) for the clean bundles
uv run python backend/scripts/ext_eval/scan_sim.py build \
    --bundle samples/bundles/loan-clean samples/bundles/kyc-clean samples/bundles/aml-clean \
    --out samples/sim --levels light med heavy

# also one JPEG per page (a phone photo per page; renders are named scan_sim_<level>_jpg)
uv run python backend/scripts/ext_eval/scan_sim.py build --bundle samples/bundles/loan-clean \
    --out samples/sim --levels med --containers pdf jpeg

# look at one page, and print the parameters that were drawn
uv run python backend/scripts/ext_eval/scan_sim.py preview --pdf samples/bundles/loan-clean/digital/bank_statement_2025-07.pdf \
    --level heavy --out /tmp/heavy.jpg
uv run python backend/scripts/ext_eval/scan_sim.py levels
```

`build` writes `samples/sim/<bundle>/{manifest.json,labels.json,ground_truth.json,scan_sim_<level>/...}`. The manifest is the source bundle's (tamper records included) with `files` and `upload_order` replaced by the simulated renders; `upload_order` therefore works with `_eval.runner.manifest_files`. Because the generator's `Render` literal does not list these names, read these manifests as plain JSON (`real_ocr.raw_doc_key_map`), not with `load_manifest`.

What the simulator does not model: a real scanner's firmware sharpening and binarisation, real printer halftone and ink spread, lens distortion, auto-exposure and HDR or AI "beautify" filters, creases, staples, stamps and handwriting, messaging-app transcoding beyond one resize and recompress, and colour (the page becomes grey ink on warm paper). It starts from the digital PDF, so it carries no PDF or EXIF metadata and no pixel-level tampers: tampers of channel `pdf_edit`, `metadata` and `image` cannot be tested on it.

## 2. Real-OCR evaluation (`real_ocr.py`, `real_ocr_eval.py`)

How it plugs in without editing the app: `Settings(ocr_backend="vision")` makes `ingest/ocr.py` read the pixels with Apple Vision (the path a text-only deployment takes), so classification runs on real OCR text. No language model is available here (Fake client, no key), so extraction cannot be the vision model: `extractor_mode="text_layer"` is used and `cascade.page_state` is wrapped inside the worker process so OCR pages are not flagged as scans, which lets the repo's deterministic text-layer extractors parse the OCR words. The result is "Apple Vision plus deterministic parser", a conservative stand-in for production (a vision model may read what the parser cannot). It is not a measurement of the production path.

Modes per render: `oracle` (the generator's ground truth stands in for OCR; delegated to the unchanged `_eval.runner`, so these are the existing eval's numbers) and `ocr`. Simulated renders have no oracle (no transformed ground-truth boxes).

Reported side by side per render and mode: documents found, statement row recall and precision, exact descriptions, running-balance chain validity, field accuracy (also by document type), page classification accuracy, pages unreadable; false alarms on clean bundles (high or medium flags, quirk-allowed excluded); tamper recall with Wilson intervals (a new flag of an expected rule relative to the same render of the base bundle).

```
# smoke test (first 4 uploads per case; numbers are not meaningful, the report says so)
uv run python backend/scripts/ext_eval/real_ocr_eval.py run --renders scan_pdf scan_sim_light \
    --modes oracle ocr --scenarios loan --tampers T01 --workers 4 --limit-files 4 --out /tmp/real-ocr-smoke

# clean bundles on every render and both modes (the cache makes a re-run cheap)
uv run python backend/scripts/ext_eval/real_ocr_eval.py run --tampers --workers 6

# plus tamper recall (default tamper ids T01 T03 T10 T12 T19 T20a T23 T58 T59 T60) on chosen renders
uv run python backend/scripts/ext_eval/real_ocr_eval.py run --workers 6 \
    --tamper-renders scan_hq scan_pdf scan_sim_light scan_sim_med scan_sim_heavy
```

Run the clean and the tamper passes as separate invocations with separate `--out` folders when the app is still being edited: the result cache is keyed by a fingerprint of `backend/app`, so an edit between two invocations makes the second one recompute, and each report then states one code state (`docs/eval-results/real-ocr/` clean, `docs/eval-results/real-ocr-tamper/` tamper recall, for example).

Defaults: renders `scan_pdf scan_hq scan_lq photo scan_sim_light scan_sim_med scan_sim_heavy`, modes `oracle ocr`, scenarios `loan kyc aml`, output `docs/eval-results/real-ocr/` (`real-ocr.md`, `extraction.csv`, `false_alarms.csv`, `recall.csv`, `results.json`, `.cache/`). Simulated bundles are built on demand under `samples/sim/` and reused. One real-OCR analysis of a 40-page bundle takes about 2 to 4 minutes (Vision is about 3.7 s per page and the pages are read one request at a time per process).

Things to know before quoting a number:

- Renders uploaded as one JPEG per page (`scan_hq`, `scan_lq`, `photo`, `scan_sim_*_jpg`): before statement assembly (`app/assemble.py`) a two-page statement became two documents and `bs_totals`, `bs_page_chain` and cross-document sums fired on the fragments whatever the OCR quality. The final code reassembles a statement when the page markers and account number allow it, and reports the pages as not reviewed otherwise; a run made on earlier code still carries the old behaviour, so check which code state a result file belongs to. Extraction metrics merge fragments by document key to isolate OCR quality, the rule tables do not. `scan_pdf` and `scan_sim_<level>` (one image-only PDF per document) remain the cleanest rows.
- The oracle in `core/llm.py` used to key on the in-file page and ignore `doc_page` in `labels.json`, which inflated oracle flags on per-page JPEG renders. The final code honours `doc_page`; oracle rows from runs made before that fix (the hand-off runs) still carry the defect.
- The app was edited by other work while this harness was written, so numbers belong to the code state of the run; `results.json` does not pin it, the cache key (`suites.code_fingerprint`) does.
- No threshold or rule was tuned on these results; the harness has none.

## 3. External forensic runner (`forensic_runner.py`)

Runs `ela_region`, `copy_move` and `noise_mismatch` (and on the untouched file only `image_editor_software`, `image_modified`, `ai_provenance_hint`) on each image in a one-file case built with `app.core.testing.make_ctx` (Fake LLM, no OCR, no network), then reports per dataset and normalisation mode, with Wilson 95% intervals: false-alarm rate on genuine images and detection rate on forged images at three strictness levels (any non-info flag, medium or high, high only), per-rule rates, Youden J (detection minus false alarm; near 0 means no signal), and, where masks exist, localisation: share of detected images with a flagged region on tampered pixels (at least 30% of the region inside the mask, the main eval's threshold), pointing-game hit next to the chance rate, and pixel IoU, precision and recall of the flagged regions against the mask.

Normalisation (`--normalise`, default all three, one table each): `raw` (as distributed: container leaks stay, metadata checks run only here), `jpeg90` (everything re-encoded as JPEG q90 at full size: removes the container leak but not the compression history), `resize1600_jpeg85` (long side 1600 then q85: resampling removes the original block grid so both classes look singly compressed, which also removes real double-JPEG evidence).

```
# RealText-V2 sample (obtained): all 115 images, three normalisations
uv run python -I backend/scripts/ext_eval/forensic_runner.py run --dataset realtext \
    --root $EXTERNAL_DATA/realtext-v2 --workers 4

# smoke test: 3 images per class
uv run python -I backend/scripts/ext_eval/forensic_runner.py run --dataset realtext \
    --root $EXTERNAL_DATA/realtext-v2 --limit-per-class 3 --out /tmp/ext-smoke

# any other dataset, once converted by hand to <root>/labels.csv (columns path,label,mask,group;
# label = forged|genuine; mask = mask image, nonzero = tampered, or a VIA JSON export)
uv run python -I backend/scripts/ext_eval/forensic_runner.py run --dataset folder --root /path/to/converted
```

Outputs under `docs/eval-results/external/`: `forensics-<dataset>.md`, `.json`, `.csv` (summary rows) and `-images.csv` (one row per image and mode).

### What each dataset does and does not represent

| Dataset | Status here | Represents | Does not represent |
|---|---|---|---|
| RealText-V2 (sample) | run | character, word and semantic edits to real-world and AI-synthesised text images, with pixel masks; English, Malay, Indonesian; generic documents (agendas, forms, posters), about 2500 x 3500 px | financial documents, scans or photos of statements, payslips or IDs; not our threat model; no test split; forged class is `.jpg` and pristine class is `.png` (format leak, so `raw` is a labelled leaky row); forgeries are largely AI-regenerated text rather than splices; reports are LLM-written; CC BY-NC 4.0 |
| Find-It-Again | not obtained (TLS certificate of the host expired; no mirror) | 988 receipt images built from SROIE, 163 forged (16%), types CPI, CPO, IMI, CUT, PIX, region labels in VIA JSON | would be the closest public match for receipts; use `--dataset folder` after a manual download |
| AIForge-Doc v2 | not obtained (gated, HTTP 401) | 3,066 GPT-Image-2 forgeries with authentic pairs on a separate zip | high-quality AI in-painting is the case this tool is least able to detect |
| SIDTD | not obtained (no data files; GitHub code repo only) | European ID cards (10 nationalities) | no SG, MY or IN documents |
| DocSplit | labels only | page order and bundle structure | no page images, no forged/genuine labels, not fraud data |

No adapter was written for datasets that could not be downloaded, apart from the generic `folder` format and a VIA JSON reader (`via_regions_to_mask`) written from the format description and tested on synthetic input only. The Find-It-Again conversion to `labels.csv` is left to whoever downloads it.

## 4. DocSplit topologies (`docsplit_eval.py`)

The DocSplit subset is label files only and its documents are generic, so `app/assemble.py` (which groups scanned bank statement pages on account number, `page x of y`, period and balance hand-over) cannot run on them. DocSplit is used as a source of real packet arrangements: every multi-page sub-document becomes one synthetic scanned statement of the same page count, uploaded one image per page in the packet's page order (truth = pages ranked by `local_doc_id_page_ordinal`). Eight cue conditions: distinct accounts, one account over consecutive months, no markers, markers lost (30%), account number lost (30%), combined noisy cues, a page missing, a duplicated statement. Reported: recovered (exact members in true order), wrong, abstained (incomplete or ambiguous, "pages not reviewed"), pair precision and recall, order accuracy. Page content is invented and the cues are assumed read correctly except where a condition says otherwise, so the numbers are an upper bound for real scans and say nothing about DocSplit's own pages.

```
uv run python -I backend/scripts/ext_eval/docsplit_eval.py run --root $EXTERNAL_DATA/docsplit --workers 6
```

## 5. FraudRAG-style local test (`fraudrag_local.py`)

Re-implemented from the published description (five categories: balance manipulation, amount digit substitution, date forgery, entity-name mismatch, fabricated transactions); it is not the original FraudRAG-2400, which is not obtainable, and nothing from that repository was run. A seeded generator writes digital PDF statements in two layouts, a manipulation module changes one thing (naive) or recomputes every dependent number (consistent), and `run_case.analyse_files` analyses them with the text-layer extractor and the Fake LLM. The rules expected to catch each variant (`EXPECTED`) were declared before the run; `None` means "cannot be caught from one statement" and is reported as a limit. The layouts were debugged on seed 11 (`DEV_SEED`); the report uses seed 20261029. PDF-forensics flags are excluded from every rate (one program made every PDF, so `pdf_producer_unexpected` fires on all of them).

```
uv run python backend/scripts/ext_eval/fraudrag_local.py run --workers 4 --out docs/eval-results/external
uv run python backend/scripts/ext_eval/fraudrag_local.py preview --dir /tmp/fraudrag-preview   # two example PDFs
```

## Honest limits (every report repeats the relevant ones)

- A forgery that is internally consistent (every total and balance recomputed, plausible values, typeset like the original) is not caught by the arithmetic rules at any scan quality. Scanning removes PDF metadata, text-layer and font evidence, so a scanned forgery is checked by fewer things than a digital one.
- High-quality AI in-painting or regeneration of text leaves none of the splice or clone traces ELA, copy-move and noise analysis look for; a low detection rate on such images (RealText-V2, AIForge-Doc) is a limit of the tool, not of the data. Pixel checks are hints; a lone ELA or copy-move region is `low` by design.
- Image-level results are not case-level results: the case score uses corroboration across detectors and documents.
- Our generated documents are clean, in four statement layouts, and are an upper bound for real documents. Simulated scans model artefacts, not a physical scan.
- Wilson intervals are wide at these sample sizes (115 images, a few dozen cases); read the intervals, not the point estimates.
